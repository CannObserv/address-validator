# Sensitive Areas — infra/

Per-module risk table for `infra/`: systemd units, memory drop-ins, ops scripts. Application code: [SENSITIVE-AREAS.md](SENSITIVE-AREAS.md). Read before touching any of these files.

| File/Module | Risk |
|---|---|
| `infra/notify_unit_failure.py` `_render_message` | Its field allowlist (`level`, `logger`, first line of `message`, `exc_type`) is the API's PII guard for the off-host failure tail: under journald a JSON record reaches WARNING+ whole, traceback included. Sending `exc_info` or all of `message` (uvicorn puts startup tracebacks there) ships tracebacks off-host. Parse before truncating; keep `--all` (#252, [LOGGING.md](LOGGING.md), `test_notify_unit_failure.py`) |
| `infra/system-slice-memory.conf` + the `MemoryLow=` lines in `infra/address-validator.service` and `infra/postgresql-memory.conf` | **A memory reservation fails silently in both directions.** A cgroup's effective `memory.low` is bounded by its ancestors' (`systemd.resource-control(5)`: *"it is generally required to set a corresponding allocation on all ancestors"*), and this host has no `memory_recursiveprot`, so dropping the `system.slice` drop-in — or forgetting it on a rebuilt host — leaves every per-service `MemoryLow=` inert while `systemctl show` keeps reporting the configured value. Verify against `/sys/fs/cgroup/system.slice/*/memory.low`, never the unit property (docs/HOST-MEMORY.md). The parent's `1G` must also stay ≥ the sum of child claims (512M + 384M): overcommit does not error, it silently downgrades each child to a proportional share. **A templated unit hides an extra level:** `postgresql@16-main.service` sits under an auto-created `system-postgresql.slice`, which is created with no resource settings — so `infra/system-postgresql-slice-memory.conf` is required or the unit's own 384M clamps to zero. This one is easy to miss twice: the unit's value reads correct and the path a reviewer expects (`system.slice/postgresql@16-main.service`) does not exist. Adding any templated unit here means adding its `system-<prefix>.slice` allocation too. |
| `infra/60-address-validator-memory.conf` | `vm.min_free_kbytes` is the reserve `GFP_ATOMIC` allocations draw on. Lowering it back toward the kernel default on this swapless host reintroduces the failure this file exists to prevent — page-allocation failures in `tailscaled`/`ksoftirqd` with **nothing OOM-killed**, so no OOM log line and no restarted unit to point at. |
| `infra/earlyoom.default` | **earlyoom can run something other than this file while its unit reads `active`.** Installing starts it on Debian's `-r 3600`, and `enable --now` never restarts it: always `systemctl restart`. Debian's unit splits `$EARLYOOM_ARGS` itself, so a space inside a regex becomes two arguments and a backslash is dropped, with no startup error. `--prefer` matches the 15-char truncated comm (`wof-libpostal-s`), so `$`-anchoring a full binary name matches nothing. The order it sets (libpostal first, postgres behind every small daemon) assumes sessions sit at -1000. `tests/unit/test_earlyoom_config.py` pins the file, and on the host the live daemon's argv and that premise (docs/HOST-MEMORY.md) |
| `infra/archive_audit.py` | Deletes audit_log rows after archival — verify GCS upload succeeded before deletion; exits when `AUDIT_ARCHIVE_BUCKET` is unset unless `--skip-upload` is explicit (it used to warn and delete anyway, #228); `ON CONFLICT DO NOTHING` in aggregation is load-bearing for idempotency, **and is why `compute_cutoff` must floor to UTC midnight** — a mid-day cutoff rolls up part of a day, the next run's rollup for the rest of it conflicts and is silently dropped, and its Parquet blob (one per day) overwrites the first slice (#228); `--backfill` stops at today's midnight for the same reason; days are bucketed in UTC (`date_trunc(..., 'UTC')`), never the session TimeZone; `ARCHIVE_SCHEMA` is the archived column list — no address-derived column may enter it: `raw_input` (address PII) is gone for good at retention, and `pattern_key` is an unsalted SHA-256 of the standardized address (confirmable/enumerable against address lists), so archiving it would undo that; no raw IP may enter it either: `client_ip` is archived as `client_ip_hmac` (HMAC-SHA256 under the archive key) + `client_ip_key_id` (#233) — never a plain SHA-256 (the IPv4 space is brute-forceable), never a raw fallback (a missing or bad key exits 1 in every mode, `--skip-upload` included), and never an IP, key or HMAC in a log line (persistent journal, #241); `ARCHIVE_SCHEMA.names` is pinned by a test; Parquet writer settings live in `_archive_writer`, shared with `rehash_archive_ips.py`; keep Parquet types compatible with already-uploaded files (integers are `int64`) |
| `infra/audit_ip_hmac.py` | The archive's IP hash (#233) and the single home of its procedures: lookup, key rotation, crypto-shredding. `canonical_ip` feeds every hash; changing it (or the HMAC construction) silently breaks "same caller" joins with every archived file and every lookup. The key is a `LoadCredential=` file or `--key-file`, never an env var: `.env` is the API's too, so `AUDIT_IP_HMAC_KEY` set anywhere is refused (#352; unit pinned by `test_audit_archive_unit.py`). `KeyConfigError` messages name the source, never the key; `IpHasher.__repr__` redacts it. The lookup CLI reads the IP via `getpass`/stdin, never argv. Stdlib only |
| `infra/rehash_archive_ips.py` | One-off rewrite of pre-#233 blobs (raw `client_ip`) in place, run once at the #233 deploy. Overwrites bucket objects: dry run by default; uploads are conditional on the generation read and re-read after; an unrecognized schema aborts. `LEGACY_ARCHIVE_SCHEMA` is pinned to what the 141 old blobs hold. Cannot serve key rotation (the raw IP is gone once rewritten) |
| `infra/audit_retention.py` | Retention parsing + `compute_cutoff`, shared by `archive_audit.py` (what is deleted) and `archive_age_check.py` (when to alert, #249); keep it stdlib-only; an archiver cadence change needs the check's `GRACE_DAYS` re-checked |
| `infra/patching_recovery_check.py` | The patching knob's recovery `health` line (#311); breaks only in the monthly window. Coupled to `audit_log.request_id`/`cache_hit`, the `x-request-id` header, and the cache storing every status but `unavailable` |
| `infra/address-validator-liveness.{sh,service,timer}` | The off-VM uptime check (#255): co-status pages on its `alert` check-ins and on its silence. Its outcomes must exit 0 — an `OnFailure=` per tick turns a co-status outage into an alert storm. The key stays a `LoadCredential=` file with the lone-newline `SetCredential=…:\n` fallback (a missing file otherwise fails every tick; an empty value is invalid syntax on systemd 255, #354) and reaches curl on stdin, never argv; `variables` stay an allowlist checked against `HealthResponseV2`'s Literals (they go to notifier). Retry ≥ a restart, run bound < `TimeoutStartSec`, URL = the knob's health line: `test_patching_knob.py`, `test_liveness_unit.py`, `tests/shell/address-validator-liveness-test.sh` |
| `infra/journald.conf.d/address-validator.conf` + the unmasked `systemd-journal-flush` | The journal persists only while the flush runs at boot (#241). A re-mask, such as a rebuild from the Feb-2026 image, leaves `Storage=persistent` inert. The journal then lives in `/run`, a reboot erases it, and nothing errors. `SystemMaxUse=512M` must equal gregoryfoster/skills#425's `zz-cannobserv-journal.conf`, which sorts last and wins. On the host, `test_journald_config.py` and the patching probe's `journal:volatile` catch it ([LOGGING.md](LOGGING.md#journal-retention--persistent-capped-at-512m)) |
| `infra/*.service`, `infra/*.timer` | Installed copies in `/etc/systemd/system/` do not follow the repo: a moved path leaves the old unit failing nightly and silently (#109, #228). Re-install with `sudo infra/install-units.sh [unit…]`; `--check` diffs installed units (sudo covers root-only `address-validator.service`). Every timer-driven service keeps `OnFailure=unit-failure@%n.service`; every restarting service (`Restart=`) keeps it too, with `RestartMode=direct` and a reachable explicit start limit — drop `direct` and a crashloop dispatches once per restart; drop the limit and it never fails, so never alerts (#248); `unit-failure@.service` never gains its own `OnFailure=` (recursion), keeps `logger` as its first `ExecStart=` and the notifier dispatch `ExecStart=-` (fail-open, #232) — all pinned by `tests/unit/test_unit_failure_hooks.py`. `libpostal.service` keeps `--log-driver=none` **and** `StandardOutput=null`: either alone leaves every parsed address in a log (#328, `test_libpostal_unit_logging.py`); its `docker rm -f`/`docker stop` keep `2>/dev/null`, or `SyslogLevel=err` puts `No such container` in every start's alert tail (#252). `Exec` script paths stay absolute for patching-hosts' restarter scan (#311, `test_patching_knob.py`). A timer without `OnCalendar=` must be a declared frequent probe (`FREQUENT_PROBES` there: cadence, no restarts, threshold sized against a restart); a probe that fails on every run, through an OOM kill or `libpostal-probe.sh`'s exit 2, alerts on every tick, not once (#256). Install refuses a linked worktree by testing whether `.git` is a file — keep it git-free: as root without `SUDO_UID`, git's "dubious ownership" error made a git-based guard fail open (#228 CR 9) |
