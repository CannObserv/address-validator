# Dependabot version updates — Design (GH #361)

**Date:** 2026-10-27
**Issue:** #361 · **Epic:** #272 · **First PR through it:** #357 · **Refs:** #232, gregoryfoster/skills#373
**Checked against:** `origin/main` `b4ababa`

## Problem

The org switched on the dependency graph, alerts and security updates on
2026-10-26, so advisories now open PRs (#357). There is no
`.github/dependabot.yml`, so nothing proposes a version update, and nothing
says so. Adopt version updates with `/adopting-dependabot`: a config that fails
a test instead of going quiet, and a written merge path.

## The constraint everything derives from

**No PR CI** (`gh pr checks` is always empty). Every Dependabot PR lands only
after a local pre-ship on its current head: one agent session per PR. Interval,
grouping and the PR limits below are chosen to keep sessions few, without
letting the limit silence an ecosystem.

**Measured 2026-10-27** (`uv tree --outdated --depth 1`, `npm outdated`): 14
runtime, 4 dev and 6 npm direct dependencies are behind. Majors among them:
`python-json-logger` 4, `python-ulid` 4; eslint 10, vitest 5, jsdom 30,
globals 17.

## Decisions

### Ecosystems

| Ecosystem | Disposition | Notes |
|---|---|---|
| `github-actions` | bot | One action (`actions/checkout@v5` → v7, not frozen: majors float through v7). One PR per action |
| `uv` | bot, with ignore | `notifier-client` is ignored: a `[tool.uv.sources]` git tag the updater doesn't move. **Manual**, per notifier's RELEASING.md; v0.3.2 exists → filed as its own issue |
| `npm` | bot | Dev-only toolchain. `.npmrc` is `engine-strict=true`, not a private index |
| `pre-commit` | bot | After the ruff change below, only `shellcheck-py` remains remote |

No ecosystem is blocked: CI has one workflow, scheduled-only, and nothing
resolves from a private index.

### Interval: weekly

Every block runs weekly (the operator's call over the proposed monthly).
Security updates ignore the schedule either way.

### Grouping

- **uv:** a `dev-tools` group (`dependency-type: development`, every update
  type), and a `runtime` group (`dependency-type: production`, `minor` +
  `patch`). Runtime **majors** stay one PR each: each is a decision against
  DEPENDENCY-POLICY's `<X+1` bound and a changelog read.
  This departs from the skill's default (every runtime dependency its own PR)
  to cut sessions. The cost: a red runtime group is bisected locally, and one
  deploy carries several runtime bumps.
- **npm:** one `js-tooling` group for `minor` + `patch`; majors one PR each.
- **github-actions, pre-commit:** one PR per action or hook repo.

Expected load: a first batch of about 10 PRs, then about 2–4 a week.

### PR limits (derived, guard-tested)

Each limit must exceed what one batch can open, or the ecosystem goes silent:

| Ecosystem | Bound (worst case) | Limit |
|---|---|---|
| uv | 23 runtime (each could be a major) + 2 groups = 25 | 30 |
| npm | 6 devDependencies + 1 group = 7 | 10 |
| github-actions | 1 action | 5 |
| pre-commit | 1 remote hook repo | 5 |

### Commit prefix

`prefix: "[chore]"`. Dependabot adds the colon after a closing bracket, giving
`[chore]: bump x from a to b`, the repo's no-issue form.

### The ruff pair: one pin

Ruff is in the dev group and in `.pre-commit-config.yaml` (`astral-sh/ruff-pre-commit`
`rev: v0.15.4`). Dependabot can move only one side per PR, and pre-ship already
runs `uv run ruff`.

**Picked: A.** The `ruff` and `ruff-format` hooks become `repo: local`,
`language: system`, `entry: uv run --frozen ruff …`. `uv.lock` is the only pin.
The dev group moves it, and pre-commit and pre-ship run the same binary by
construction.

Rejected:
- **B**, ignore ruff in pre-commit and hand-bump `rev:` after each dev PR: a
  commit onto Dependabot's branch or a drift window, every time.
- **C**, the reverse of B: same cost.

### The cadence workflow

`context-cadence.yml` is generated by `install-cadence.sh` and runs only on
schedule or dispatch.

- **The bump:** take checkout v5 → v7 from the bot.
- **The run:** the PR's CI never runs this workflow, so the operator dispatches
  it once after landing (the PAT can't dispatch).
- **Re-renders:** a re-render writes `@v5` back. Until the generator stops
  downgrading, compare the `uses:` lines after any re-render and restore any
  that went backwards.
- **Upstream:** add this repo's evidence to gregoryfoster/skills#373. File the
  template's own checkout bump upstream, as issues only.

### Version bounds

DEPENDENCY-POLICY requires `>=X.Y,<X+1`. Five dev entries have no upper bound:
ruff, pre-commit, pytest, pytest-cov, parserator. They gain `<X+1`, and a guard
test keeps every runtime and dev requirement bounded. That keeps
`increase-if-necessary` proposals inside the policy's form: an in-range bump
is a lock change, and a major is its own PR.

## Tests

- `tests/ci/test_dependabot.py`: the skill's asset with only its ADAPT block set.
  - `ENABLED`: all four ecosystems.
  - `IGNORED`: `notifier-client`.
  - `COMMIT_TYPES`: the bracketed forms.
  - `SHA_PINS = False`: the policy decision isn't taken here.

  **Mutation-checked:** each break in config-keys.md's table, applied in turn,
  fails a guard. The evidence goes in the PR.
- `tests/ci/test_dependabot_repo.py`: what the asset doesn't cover here.
  - the npm and pre-commit limits, derived from `package.json` and the
    remote-repo count;
  - ruff has one pin (no `ruff-pre-commit` repo; the ruff hooks run `uv run`);
  - every Python requirement carries an upper bound.
- `pyyaml` and `packaging` are declared in the dev group, because the tests
  import them (both arrive only transitively today).

## Merge path

Goes in `docs/DEPENDENCY-POLICY.md`, not AGENTS.md. It is merge-paths.md's
GitHub-merge path, gated by pre-ship instead of CI:

1. Read the changelog across every version between.
2. If main moved, `@dependabot rebase`, and wait until `headRefOid` changes.
3. Check out that head in a worktree, then run:
   - `uv sync`;
   - `uv run pre-commit clean && uv run pre-commit run --all-files`;
   - pre-ship;
   - `uv audit --frozen`;
   - `uv lock --check`.
4. Land it with `gh pr merge <N> --merge --match-head-commit <sha>`.
5. Deploy only if it's a runtime bump: a `runtime` group, a runtime major or a
   security update to a runtime package. That needs the operator's approval as
   its own step: pull the main checkout, `uv sync`, restart (clock checked).
   Dev, npm, pre-commit and actions bumps need no restart.
6. Dispatch the cadence workflow once if the bump touched it.

**One PR at a time,** each with the operator's approval, for the first batch.
The no-PR-CI trade-off is recorded there too: a PR workflow running ruff and
pytest would let a bump gate itself and cut each landing to a review. That's
out of scope here (`auditing-ci-cost`).

## Delivery

Two merges, so turning the bot on is its own step:

1. **Prep PR:** this doc; the sweep test; the dev bounds and the
   `pyyaml`/`packaging` declarations; the ruff local hooks; the repo-local guard
   tests that don't need the config; the DEPENDENCY-POLICY merge path; a
   `docs/SKILLS.md` note if anything is repo-specific.
2. **Activation PR:** `.github/dependabot.yml` and `tests/ci/test_dependabot.py`,
   with the mutation evidence. **Pushing it needs the operator's explicit go,**
   because PRs open within a minute of the merge.

Then:
- `check-dependabot.sh` on `config`, `limit:*`, `update-runs` and `graph`;
- the operator confirms alerts and security updates, which the PAT can't read;
- #357 lands first on the new path (it is a dev-only, transitive bump: filelock
  3.25.2 → 4.2.1, as proposed, not 4.2.4). If the hooks break on 4.x, stop and
  report; don't pin below 4;
- the rest of the first batch, one PR at a time.

## Non-goals

- Adding PR CI.
- SHA-pinning actions.
- Changing repository settings.
- Any AGENTS.md addition.
